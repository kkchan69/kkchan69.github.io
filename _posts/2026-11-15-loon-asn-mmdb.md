## 起因

给我的规则仓库做 Loon 模板时发现：Loon 匹配 `IP-ASN` 规则（我有一组 Telegram 的 ASN 规则）用的是一个单独的 ASN 数据库，靠 `ipasn-url` 指定。一开始我图省事，用了第三方的 GeoLite2-ASN 镜像。

但我上一篇刚把国家库换成自建的（[《自己动手做一个 CN+MY 的 GeoIP 数据库》](/2026/11/12/geoip-cn-my.html)），模板里所有数据库都从我自己仓库下载、就剩这一个挂在别人那里，怎么看怎么别扭。干脆也自建。

## 先泼一盆冷水：这个不能「只做 CN+MY」

国家库可以只切两个国家，因为问题本身就是「这个 IP 在哪个国家」。ASN 库回答的是另一个问题：「这个 IP 属于哪个运营商（自治系统）」。

我的 Telegram 规则里那几个 ASN——AS62041、AS62014、AS59930、AS44907、AS211157——全是境外运营商。真要按国家把库切小，这几条规则当场就废了。所以 ASN 库的正确做法是**做全量**，它和国家库是两个维度，别混为一谈。

## 数据与流水线

数据源用 iptoasn.com：它把全球 BGP 路由表整理成 TSV 文件（IPv4、IPv6 各一份），每行是一个 IP 区间对应的 ASN 和运营商名称。

流水线分两步：

1. **区间转 CIDR**：用 Python 把每个起止区间汇总成 CIDR 列表，跳过 AS0（未路由的段）
2. **写库**：用 Go 的 `mmdbwriter` 写成 `GeoLite2-ASN` 格式的 .mmdb

中间踩了一个小坑：写入某些 IPv6 保留段时构建器直接报错退出，要打开 `IncludeReservedNetworks` 才肯收——官方库里这些段本来也是有记录或明确留空的，行为对齐就行。

最终成果：**1,013,901 个网段，约 10 MB**。

## 验证

老规矩，做完必须验：

- Telegram 的 IP（91.108.4.1）→ **AS62041** ✓
- 1.1.1.1 → AS13335（Cloudflare）✓
- 8.8.8.8 → AS15169（Google）✓
- 私有地址 → 无记录，和官方库行为一致 ✓
- 传到 GitHub 后从 raw 地址下载回来，和本地比对哈希，一致才算数 ✓

## 结果

两份 Loon 模板的 `ipasn-url` 都换成了我自己仓库的 `geoip/asn.mmdb`（v1.10.0）。至此，我的 Surge 和 Loon 模板用到的每一个数据库——国家库、ASN 库——都托管在自己的仓库里，不再依赖任何第三方镜像。镜像哪天挂了、跑路了，都跟我没关系。
